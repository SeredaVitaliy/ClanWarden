# Архитектура

[English](ARCHITECTURE.md) · **Русский**

## Структура

```
clanwarden/
├── __main__.py          точка входа: `python -m clanwarden [run|check]`
├── app.py               сборка: зависимости, роутеры, фоновая задача
├── config.py            чтение и проверка переменных окружения
├── db.py                SQLite: схема, миграции, запросы
├── texts.py             сборка сообщений (HTML) из строк каталога
├── i18n/                каталоги строк: en.py, ru.py + переводчик
├── coc/
│   ├── client.py        HTTP-клиент CoC API: ошибки, кэш
│   ├── models.py        dataclass-модели: War, WarMember, CwlGroup…
│   └── tags.py          нормализация тегов
├── services/
│   ├── wars.py          логика войн и ЛВК (поиск своей войны, таблица)
│   ├── notifications.py чистая функция: какие уведомления пора отправить
│   └── notifier.py      фоновый цикл: опрос API → план → отправка → журнал
└── bot/
    ├── middlewares.py   настройки группы и переводчик в хендлер + фильтр тем
    ├── helpers.py       права админа, выбор клана, тексты ошибок API
    ├── keyboards.py     инлайн-клавиатуры и callback data
    ├── views.py         сборка ответов (общая для команд и кнопок)
    └── handlers/        команды: war, accounts, admin, common
```

Зависимости идут сверху вниз: `bot` → `services` → `coc`, `db`. Модули `coc` и `services` ничего не знают про Telegram, поэтому их можно тестировать без него.

## Ключевые решения

### Уведомления: «состояние + журнал» вместо таймеров

Самый очевидный способ — поставить таймер «через N часов отправить напоминание». Он ломается при перезапуске бота, при простое сервера и когда бота добавили посреди войны.

Здесь сделано иначе. Раз в пару минут бот смотрит на текущее состояние войны и спрашивает чистую функцию `plan_events(war, now, settings, already_sent)`, что пора отправить. Отправленное записывается в таблицу `sent_events` с ключом *(чат, война, событие)*. В итоге:

- после перезапуска ничего не дублируется: журнал лежит в базе;
- если сервер лежал, напоминание уйдёт сразу после подъёма, пока не закрылось его окно;
- у «старых» событий есть грейс-период: если бота добавили через 10 часов после начала войны, «Война началась!» он не пришлёт.

`plan_events` не делает ввода-вывода, поэтому все пограничные случаи покрыты обычными unit-тестами.

### Идентификатор войны

API не отдаёт ID обычной войны. Ключ собирается из тегов обоих кланов (отсортированных, чтобы не зависеть от стороны) и времени начала подготовки. Для ЛВК есть `warTag`, используется он.

### ЛВК: найти свою войну

`/leaguegroup` возвращает 8 кланов и по 4 войны на раунд, но не говорит, какая из них ваша. В войне ЛВК ваш клан может оказаться и в поле `clan`, и в `opponent`. В старой версии бот брал первую идущую войну группы, а она могла быть чужой.

Сейчас сервис идёт по раундам с конца, находит войну с нашим тегом и разворачивает её (`War.oriented`), чтобы наш клан всегда был в `clan`. Найденный `warTag` кэшируется на сезон и раунд, поэтому следующий опрос делает один запрос вместо четырёх. Завершённые войны ЛВК кэшируются навсегда: они уже не изменятся.

### Один опрос на клан

Если клан подключён в двух группах, API опрашивается один раз, а результат рассылается в обе. Плюс короткий кэш в клиенте и склейка одинаковых одновременных запросов.

### Привязка аккаунтов

У тега ровно один владелец (`PRIMARY KEY (player_tag)`): иначе упоминания уходили бы не тем людям. Свободный тег можно привязать без проверки. Чтобы забрать уже занятый, нужен одноразовый API-токен из настроек игры, который бот проверяет через `POST /players/{tag}/verifytoken`.

### История войн и статистика

API игры отдаёт только *текущую* войну, а в `/warlog` нет данных по игрокам. Поэтому бот ведёт свою историю: как только notifier видит войну в состоянии `warEnded`, он сохраняет её (`wars`) и атаки каждого участника (`war_members`). Запись идемпотентна (`INSERT OR IGNORE` по ключу войны), а множество в памяти избавляет от похода в базу на каждом опросе. `/stats` — обычная SQL-агрегация за последние N войн или за сезон ЛВК.

Заодно закрыта реальная дыра: когда начинается новый раунд ЛВК, предыдущий заканчивается в ту же минуту. Опросчик, который смотрит только на «идёт бой» и «подготовку», никогда не увидит войну ЛВК завершённой. Теперь `cwl_rounds` возвращает и последний завершённый раунд (в том числе после окончания сезона), поэтому работают и итоги раундов, и статистика.

### Картинки в README

`scripts/render_previews.py` собирает демо-войны, прогоняет их через настоящие функции `texts` на обоих языках и делает скриншот через headless Chromium. Поэтому картинки в README всегда совпадают с тем, что реально отправляет бот. Рендер даже поймал баг в подсчёте суммарного разрушения в таблице ЛВК.

### Почему SQLite

Бот ставится одним контейнером на маленький VPS, нагрузка — десятки записей в минуту. Отдельная СУБД только усложнила бы установку. Миграции версионируются через `PRAGMA user_version`.

### Почему HTML, а не Markdown

В никах игроков встречаются `*`, `_`, `` ` ``, и Markdown-разметка от них ломается: старая версия из-за этого переотправляла сообщения без форматирования. В HTML достаточно экранировать `<`, `>`, `&`.

### Локализация (i18n)

Весь текст для пользователя лежит в каталогах `clanwarden/i18n/en.py` и `ru.py` под ключами. В коде нет строк интерфейса: везде вызов `t("ключ", параметры)`. Middleware определяет язык и кладёт переводчик `t` в каждый хендлер:

- в группе — язык, выбранный через `/language`; при первой настройке (`/setclan`) берётся язык Telegram админа;
- в личке — выбранный пользователем язык, иначе язык его Telegram.

Уведомления фоновой задачи уходят на языке группы, личные напоминания — на языке игрока. Если ключа нет в каталоге, берётся английский, поэтому неполный перевод не ломает бота. Тест проверяет, что у всех каталогов одинаковые ключи и плейсхолдеры. Команды в меню «/» Telegram тоже регистрируются на обоих языках (`set_my_commands` с `language_code`).

### Зависимости без глобальных переменных

Клиент API, база и сервисы создаются в `app.py` и кладутся в `Dispatcher`. aiogram передаёт их в хендлеры по имени аргумента (`db`, `coc`, `wars`). Поэтому в тестах их легко подменить заглушками.

| `test_models.py` | разбор ответов API, теги, разворот войны, итог |

## Что можно улучшить дальше

- Автоматические итоги сезона ЛВК в группу.
- Больше языков: добавить файл каталога.
- Автообновление ключа API через логин developer-аккаунта для серверов с динамическим IP.
- Webhook вместо long polling для крупных инсталляций.
